**Rovunet Panel — открытый самостоятельно размещаемый инструмент для развёртывания и управления многопротокольным доступом в интернет на совместимых Linux-серверах.** Он даёт каждому пользователю несколько путей подключения, чтобы доступ не зависел от одного протокола или от определённого состояния сети.

Панель объединяет установку и настройку управляемых протоколов, создание пользователей, экспорт клиентских конфигураций и управление службами systemd в работу из командной строки с интерактивным меню. Доступные пути: VLESS поверх WebSocket, NaiveProxy, прямой SSH, SSH поверх TLS, SOCKS5, семейства DNS-туннелей DNSTT, NoizDNS, VayDNS, Slipstream и Soar, а также ядра Xray (VLESS REALITY, VLESS XHTTP, Hysteria2 и WireGuard). Средства диагностики и резервного копирования помогают обслуживать сервер и искать неисправности.

Панель создана для работы с [приложением Rovunet для Android](https://github.com/msVPNco/rovunet-android): собственный формат экспорта передаёт вместе со связанными путями метаданные коллекции. Приложение проверяет подключение через сам туннель и спрашивает разрешения перед переходом к резервному DNS-этапу. Для других совместимых клиентов есть стандартные ссылки VLESS.

**Объём поддержки:** ядра Xray устанавливаются и управляются командой `rovunet core-install` (`core-plan` по-прежнему только создаёт файлы для ручного развёртывания). Качество и доступность подключения зависят от сети, настроек сервера и выбранного протокола. Различие между готовыми функциями и оставшейся работой описано в [состоянии интеграции и приоритетах разработки](docs/ROVUNET-STATUS.md).

> **Состояние проекта: ранний выпуск, активная разработка.** Перед рабочим использованием проверьте нужные протоколы в своей среде и сделайте резервную копию настроек командой `rovunet backup`.

## Быстрая установка

На новом сервере с Ubuntu 20.04+ или Debian 10+, с правами root:

```bash
curl -fsSL https://raw.githubusercontent.com/msVPNco/rovunet-panel/main/install.sh | sudo bash
```

Установщик спрашивает, какие протоколы включить, настраивает их, создаёт
первого пользователя и печатает все его конфигурации. Затем:

```bash
sudo rovunet                # интерактивное меню
sudo rovunet users add      # добавить пользователя
sudo rovunet users configs  # снова показать конфигурации всех пользователей
sudo rovunet diag           # проверить службы, порты, ключи и DNS
```

Переходите с SlipGate? См. [перенос сервера](docs/GUIDE.md#quick-start);
настройки, туннели и пользователи сохраняются.

## Протоколы

| Протокол | Как передаётся трафик | Порт | Когда использовать |
|---|---|---|---|
| **VLESS за NaiveProxy** | WebSocket за Caddy с настоящим сертификатом | 443/tcp | Первый выбор: быстро, выглядит как обычный HTTPS-сайт |
| **NaiveProxy** | HTTP/2-прокси с сайтом-приманкой | 443/tcp | Когда TLS до вашего домена проходит |
| **SSH поверх TLS (StunTLS)** | SSH внутри TLS/WebSocket, на 443 | 443/tcp | Альтернатива VLESS на том же порту |
| **Прямой SSH** | Обычный SSH | 22/tcp | Быстро, где открыт порт 22 |
| **VLESS через Cloudflare** | WebSocket через CDN Cloudflare | 2053/tcp | Когда IP сервера заблокирован; медленнее |
| **DNSTT / NoizDNS** | Зашифрованный DNS-туннель | 53/udp | Для ограниченных сетей; скорость зависит от резолвера и пути |
| **VayDNS** | DNS-туннель с настраиваемым форматом | 53/udp | Как DNSTT, но с большим числом настроек |
| **Slipstream** | QUIC поверх DNS | 53/udp | Экспериментальный |
| **Soar** | Многопутевой DNS с поиском резолверов | 53/udp | Когда DNS-резолверы фильтруются неравномерно |
| **SOCKS5** | Обычный SOCKS5 | 1080/tcp | Только для открытых сетей (без шифрования) |
| **VLESS REALITY** (ядро Xray) | TLS, похожий на настоящий сайт, сертификат не нужен | любой свободный TCP-порт | Когда TLS до известных сайтов проходит |
| **VLESS XHTTP** (ядро Xray) | VLESS поверх HTTP-запросов, настоящий сертификат | любой свободный TCP-порт | За CDN или где WebSocket заблокирован |
| **Hysteria2** (ядро Xray) | QUIC с собственным управлением перегрузкой, настоящий сертификат | любой свободный UDP-порт | Сети с потерями и нестабильные сети, где UDP проходит |
| **WireGuard** (ядро Xray) | Стандартный WireGuard, отдельный файл на устройство | любой свободный UDP-порт | Где WireGuard не заблокирован |

Пригодность протокола зависит от сервера, оператора и текущего состояния сети. Это рекомендации по выбору, а не гарантия доступности и не результаты сравнительных тестов. Приложение Rovunet проверяет пути подключения.

Ядра Xray работают как отдельные службы рядом с туннелями:

```bash
sudo rovunet core-install --name r1 --protocol reality --host SERVER_IP \
  --target www.microsoft.com:443 --sni www.microsoft.com --port 8443 --devices 5
sudo rovunet core-list
sudo rovunet core-remove r1
```

Сначала проверяется, свободен ли порт; Xray сверяется с контрольными суммами
выпуска и проверяет конфигурацию до запуска; затем открывается порт TCP или UDP.
Каждое устройство получает свой файл в `/etc/rovunet/core/<имя>/clients/`.
XHTTP и Hysteria2 требуют `--cert` и `--key` для сертификата, действительного для `--sni`.

## Клиентские приложения

[Выпуски Rovunet для Android](https://github.com/msVPNco/rovunet-android/releases) содержат опубликованные установщики и исходные файлы. Перед установкой прочитайте [текущее состояние приложения](https://github.com/msVPNco/rovunet-android/blob/main/docs/STATUS.md) и заметки о подписи и миграции; приватные сборки не являются обновлением публичной версии на месте. См. [состояние интеграции](docs/ROVUNET-STATUS.md).

- **[Rovunet для Android](https://github.com/msVPNco/rovunet-android)**
  (рекомендуется): импортирует ссылки `rovunet://`, объединяет пути каждого
  пользователя в одну коллекцию, подключает выбранный путь без обязательного пинга и предлагает отдельные HTTPS-проверки через настоящий туннель.
  [Скачать последний выпуск](https://github.com/msVPNco/rovunet-android/releases).
- **Стандартные клиенты**, например v2rayNG, Hiddify или NekoBox: используйте ссылки
  `vless://`, которые панель печатает рядом с каждой конфигурацией VLESS.

```bash
sudo rovunet export-clients --user USER --format rovunet
```

## Требования

- Linux-сервер (Ubuntu 20.04+, Debian 10+ или аналог) с правами root
- Домен, DNS которого вы контролируете, направленный на сервер (см.
  [схему доменов](docs/GUIDE.md#domain-layout))
- Открытые порты для включаемых протоколов: как минимум 53/udp, 80/tcp и 443/tcp
