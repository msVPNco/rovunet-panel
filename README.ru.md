Rovunet Panel — открытый инструмент, превращающий Linux-сервер в многопротокольный сервер доступа. Он устанавливает каждый протокол как службу systemd и управляет им, создаёт пользователей и экспортирует их клиентские конфигурации, чтобы у каждого пользователя было несколько независимых путей подключения вместо зависимости от одного протокола или одного состояния сети.

## Возможности

- **Управление прокси, SSH, DNS-туннелями и протокольными ядрами**, включая AmneziaWG, Shadowsocks 2022, Trojan TLS и VLESS Encryption, из одного инструмента с интерактивным меню.
- **Учётные данные пользователей на путях с аутентификацией** и адресное обновление четырёх добавленных протоколов. Прямой Soar использует общий ключ.
- **Готовые к импорту конфигурации**: собственные ссылки `rovunet://` для [приложения Rovunet](https://github.com/msVPNco/rovunet-app), стандартные `vless://`, `hysteria2://` и файлы WireGuard для других клиентов.
- **Работа через порт 443**: VLESS и SSH over TLS делят с NaïveProxy домен, порт и сертификат Let's Encrypt за сайтом-приманкой.
- **Безопасная эксплуатация**: обновления с проверкой контрольных сумм и откатом, проверка конфигураций до развёртывания, полное резервное копирование и восстановление сервера.
- **Диагностика**: панель в реальном времени, проверки состояния, сроки действия сертификатов и журналы служб.
- **Лимиты и ссылки подписки**: безлимитные и ограниченные пользователи (дни и/или ГБ, проверка каждые 5 минут) и одна ссылка подписки на пользователя со всеми его конфигурациями для меню Subscriptions в приложении.
- **Несколько адресов одного сервера**: добавьте другие IP сервера, и ссылки несут каждую конфигурацию, привязанную к адресу, по одному разу на адрес — блокировка одного IP не отрежет пользователей.
- **Автоматический выбор цели REALITY**: сайт-маскировка выбирается из набора популярных сайтов, которые редко блокируют. Новая установка добавляет второе ядро REALITY на другом порту с сайтом другой компании, так что у пользователя два пути входа.
- **Постоянные ссылки подписки и понятные имена**: обычное обновление сохраняет токены и ID профилей. Android использует `<token>.json`, Windows — `<token>.windows.json` со своим набором совместимых протоколов. Обновите сохранённую подписку для получения новых отображаемых имён.

## Протоколы

| Протокол | Как передаётся | Порт | Когда использовать |
|---|---|---|---|
| **VLESS over WebSocket** (через NaïveProxy) | WebSocket + TLS, настоящий сертификат | 443/tcp | Первый выбор, где работает HTTPS |
| **VLESS over WebSocket** (через Cloudflare) | WebSocket через CDN Cloudflare | 2053/tcp | Когда IP сервера заблокирован |
| **NaïveProxy** | HTTP/2 + TLS с сайтом-приманкой | 443/tcp | Где проходит TLS до вашего домена |
| **SSH over TLS** (StunTLS) | SSH внутри TLS / WebSocket | 443/tcp | Альтернатива на том же порту |
| **SSH** | Обычный SSH | 22/tcp | Где открыт порт 22 |
| **SOCKS5** | Обычный SOCKS5 без шифрования | 1080/tcp | Только открытые сети |
| **DNSTT** / **NoizDNS** | Зашифрованный DNS-туннель | 53/udp | Ограниченные сети, где проходит DNS |
| **VayDNS** | DNS-туннель с настраиваемым форматом | 53/udp | Как DNSTT, с большим числом настроек |
| **Slipstream** | QUIC поверх DNS | 53/udp | Экспериментальный |
| **Soar** | Многопутевой DNS с поиском резолверов | 53/udp | Неравномерно фильтруемые резолверы |
| **VLESS + REALITY** (Xray) | TCP, имитирует настоящий TLS-сайт | любой TCP | Где проходит TLS к известным сайтам |
| **VLESS + XHTTP** (Xray) | HTTP-запросы поверх TLS | любой TCP | За CDN или где заблокирован WebSocket |
| **Hysteria 2** (Xray) | QUIC | любой UDP | Сети с потерями, где проходит UDP |
| **WireGuard** (Xray) | UDP | любой UDP | Где WireGuard не заблокирован |
| **AmneziaWG** | UDP-туннель в пользовательском пространстве | любой UDP | Дополнительная альтернатива WireGuard |
| **Shadowsocks 2022** (Xray) | TCP и UDP | любой TCP/UDP | Совместимость; закреплённый Xray считает протокол устаревающим |
| **Trojan TLS** (Xray) | TCP + TLS с доверенным сертификатом | любой TCP | Совместимость TLS; Trojan без Flow устаревает в закреплённом Xray |
| **VLESS Encryption** (Xray) | TCP + шифрование ML-KEM/X25519 | любой TCP | Клиенты с поддержкой закреплённого формата шифрования |

Пригодность зависит от сервера, оператора и сети; это рекомендации, а не гарантии. Подробнее — в разделе [Протоколы](docs/ru/protocols.md).

**v1.21.2:** проверенная полная конфигурация выдаёт **24 профиля Android и 24 профиля Windows**, а не 24 независимых протокола. Количество зависит от установленных служб и типа аккаунта. Текущий Windows получает оба; старая Beta пропускает неподдерживаемый AWG и сохраняет остальные записи. Все четыре новых протокола исключены для аккаунтов с лимитом трафика; три новых протокола Xray после истечения срока или удаления запрещают новые сеансы, но уже открытые потоки могут продолжаться. Точного ограничения одновременно подключённых устройств нет. См. [управляемые протоколы и совместимость](docs/MANAGED-PROTOCOLS.md).

**Автоматическая полная настройка (v1.21.2):** обычная установка и Quick Wizard выбирают полный набор туннелей и оба backend. Обновление автоматически добавляет недостающие ядра, сохраняя пользователей, ключи, имена ядер и URL подписок. Настроенный сервер с 20 профилями получает 24 профиля Android / 24 Windows без четырёх ручных установок. Для неполной базовой настройки интерактивное обновление запрашивает недостающие DNS/домены. Нужны действующий сертификат NaiveProxy, TUN и свободные порты; при ошибках выводятся фактические количества и незавершённый статус. `sudo rovunet complete-setup` продолжает настройку, `sudo rovunet install --custom` открывает выборочную установку. Ограничения протоколов для тарифов с лимитом трафика сохраняются.

## Быстрый старт

На новом сервере с Ubuntu 24.04 LTS или Debian (systemd; runtime compatibility required), с правами root:

```bash
curl -fsSL https://raw.githubusercontent.com/msVPNco/rovunet-panel/v1.21.2/install.sh -o rovunet-install.sh
python3 -c 'import hashlib,pathlib; assert hashlib.sha256(pathlib.Path("rovunet-install.sh").read_bytes()).hexdigest()=="a8aaa38d979049fa5e42c9f8f444e519d28625d1d67872ddaeff2d0dfc6b3498", "Installer checksum mismatch"'
sudo bash rovunet-install.sh
```

Установщик спрашивает, какие протоколы включить, настраивает их, создаёт первого пользователя и печатает его конфигурации. Затем:

```bash
sudo rovunet                 # interactive menu
sudo rovunet users add       # add a user
sudo rovunet users configs   # print every user's configurations
sudo rovunet diag            # check services, ports, keys and DNS
```

Требования: доступ root, домен, DNS которого вы контролируете, и открытые порты для включаемых протоколов (как минимум 53/udp, 80/tcp и 443/tcp). См. [Начало работы](docs/ru/getting-started.md).
