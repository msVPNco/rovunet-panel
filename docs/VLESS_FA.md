# راهنمای VLESS در SlipGate

این نسخه از SlipGate یک تونل جدید به اسم **VLESS روی WebSocket** دارد که پشت کلودفلر کار می‌کند. کاربر به IP کلودفلر وصل می‌شود و کلودفلر ترافیک را به سرور شما می‌رساند. به همین دلیل IP سرور پنهان می‌ماند و فیلتر شدنش اتصال را قطع نمی‌کند.

این تونل با پروفایل VLESS همین اپ فعلی SlipNet کار می‌کند و اپ به هیچ تغییری نیاز ندارد. با کلاینت‌های دیگر VLESS مثل v2rayNG، Hiddify و NekoBox هم کار می‌کند.

## ویژگی‌ها

- **شناسه‌ی جدا برای هر کاربر:** هر کاربر SlipGate یک UUID مخصوص خودش دارد که از نام کاربری، رمز و یک کلید مخفی روی سرور ساخته می‌شود. رمز کاربر هیچ‌وقت داخل لینک قرار نمی‌گیرد.
- **لغو فوری دسترسی:** اگر کاربری را حذف کنید یا رمزش را عوض کنید، UUID قبلی‌اش ظرف چند ثانیه از کار می‌افتد و نیازی به ری‌استارت نیست.
- **مقاوم در برابر شناسایی:** هر درخواستی غیر از مسیر مخفی WebSocket، صفحه‌ی پیش‌فرض nginx را می‌بیند. یعنی سرور از بیرون مثل یک وب‌سرور معمولی به نظر می‌رسد.
- **امنیت سرور:** کاربران فقط به آدرس‌های عمومی اینترنت دسترسی دارند و به سرویس‌های داخلی سرور (مثل 127.0.0.1) راه ندارند. پورت ۲۵ (ایمیل) هم به‌صورت پیش‌فرض بسته است تا IP سرور به خاطر اسپم در لیست سیاه نرود.
- **پایداری پشت کلودفلر:** سرور هر ۳۰ ثانیه یک ping می‌فرستد تا کلودفلر اتصال‌های بی‌فعالیت را قطع نکند.

## ۱. نصب یا جابه‌جایی به این نسخه

**سرور تازه:**

</div>

```bash
curl -fsSL https://raw.githubusercontent.com/msVPNco/slipgate/main/install.sh | sudo bash
```

<div dir="rtl">

**سروری که الان SlipGate اصلی رویش نصب است:** تنظیمات، کاربرها و تونل‌های فعلی دست‌نخورده می‌مانند:

</div>

```bash
sudo curl -fsSL -o /usr/local/bin/slipgate https://github.com/msVPNco/slipgate/releases/latest/download/slipgate-linux-amd64
sudo chmod +x /usr/local/bin/slipgate
sudo slipgate post-update
```

<div dir="rtl">

اگر سرورتان ARM است، به جای `amd64` بنویسید `arm64`. از این به بعد دستور `sudo slipgate update` هم از همین نسخه به‌روزرسانی می‌گیرد.

## ۲. تنظیم کلودفلر

1. **رکورد DNS:** یک رکورد A بسازید، مثلاً `cdn.example.com`، که به IP سرور اشاره کند. **Proxy status** را روی **Proxied** (ابر نارنجی) بگذارید.
2. **حالت SSL:** در بخش **SSL/TLS** و بعد **Overview**، حالت رمزنگاری را **Full** بگذارید. حالت Flexible کار نمی‌کند و حالت Full (strict) هم گواهی خودامضای سرور را قبول نمی‌کند.
3. **WebSocket:** در بخش **Network** مطمئن شوید **WebSockets** روشن است (به‌صورت پیش‌فرض روشن است).
4. **بقیه‌ی رکوردها:** رکوردهای تونل‌های DNS و NaiveProxy باید مثل قبل **DNS only** (ابر خاکستری) بمانند.

**انتخاب پورت:** کلودفلر فقط این پورت‌های HTTPS را پروکسی می‌کند: ۴۴۳، ۲۰۵۳، ۲۰۸۳، ۲۰۸۷، ۲۰۹۶ و ۸۴۴۳. اگر NaiveProxy روی ۴۴۳ است، برای VLESS یکی از بقیه را بردارید، مثلاً ۲۰۵۳. اگر شرکت ارائه‌دهنده‌ی سرور فایروال جداگانه دارد، این پورت را آنجا هم باز کنید.

## ۳. ساختن تونل

**از منو:** دستور `sudo slipgate` را اجرا کنید، بعد Tunnels، بعد Add و گزینه‌ی VLESS را انتخاب کنید. بقیه را خود پنل می‌پرسد.

**با یک دستور:**

</div>

```bash
sudo slipgate tunnel add --transport vless --tag vless --domain cdn.example.com --cdn yes --listen-port 2053
```

<div dir="rtl">

اگر هنوز کاربری نساخته‌اید، پنل بعد از ساختن تونل پیشنهاد ساختنش را می‌دهد. با `sudo slipgate users` هم می‌شود کاربر اضافه کرد.

## ۴. گرفتن لینک برای کاربر

</div>

```bash
sudo slipgate tunnel share vless --user alice
```

<div dir="rtl">

این دستور دو لینک می‌دهد:

- **لینک `slipnet://`:** برای اپ SlipNet.
- **لینک `vless://`:** برای v2rayNG، Hiddify، NekoBox، Streisand و بقیه. SlipNet هم این لینک را قبول می‌کند.

برای دیدن لینک همه‌ی کاربرها و همه‌ی تونل‌ها یک‌جا: `sudo slipgate users configs`

## ۵. IP تمیز کلودفلر

اگر IPهای معمول کلودفلر روی اینترنت کاربر کند یا مسدود باشند، یک IP تمیز پیدا کنید و یکی از این دو کار را انجام بدهید:

- **در اپ:** در SlipNet پروفایل را ویرایش کنید و فیلد **CDN IP** را عوض کنید. فقط روی همان گوشی اثر دارد.
- **روی سرور:** دستور زیر را بزنید تا در همه‌ی لینک‌هایی که از این به بعد ساخته می‌شوند، آن IP قرار بگیرد:

</div>

```bash
sudo slipgate tunnel edit vless --cdn-address 104.16.0.1
```

<div dir="rtl">

## ۶. لایه‌ی امنیتی اضافه با SSH (اختیاری)

کلودفلر وسط مسیر است و می‌تواند سرآیند VLESS (مقصد اتصال‌ها) را ببیند. اگر این برایتان مهم است، در SlipNet از قابلیت **Chain** استفاده کنید: اول پروفایل VLESS و بعد یک پروفایل SSH با IP عمومی سرور، پورت ۲۲ و همان نام کاربری و رمز. با این کار کلودفلر فقط ترافیک رمزشده‌ی SSH را می‌بیند.

## عیب‌یابی

- **وضعیت کلی:** `sudo slipgate diag` سرویس، پورت، کلید و گواهی را بررسی می‌کند.
- **لاگ تونل:** `sudo slipgate tunnel logs vless`
- **خطای ۵۲۱ یا ۵۲۲ کلودفلر:** کلودفلر به سرور نمی‌رسد. پورت را در فایروال ارائه‌دهنده‌ی سرور باز کنید و مطمئن شوید پورت جزو پورت‌های مجاز کلودفلر است.
- **خطای ۵۲۵ یا ۵۲۶ کلودفلر:** حالت SSL درست نیست. آن را روی **Full** بگذارید.
- **«WebSocket upgrade failed» در اپ:** مسیر (path) لینک با سرور یکی نیست. لینک را دوباره بگیرید.
- **اپ وصل می‌شود ولی هیچ سایتی باز نمی‌شود:** کاربر حذف شده یا رمزش عوض شده است. لینک تازه بگیرید.

## محدودیت‌ها

- **فقط WebSocket:** پروتکل‌های Reality و XHTTP در این تونل نیستند، چون اپ فعلی SlipNet فقط VLESS روی WebSocket را پشتیبانی می‌کند.
- **UDP ساده:** UDP به شکل ساده پشتیبانی می‌شود، ولی حالت Mux/XUDP نه. اگر کلاینتی مثل v2rayNG خطا داد، Mux را در آن خاموش کنید.
- **WARP:** خروجی این تونل از مسیر WARP رد نمی‌شود.
