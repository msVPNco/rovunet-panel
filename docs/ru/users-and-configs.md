# Пользователи и клиентские конфигурации

[Документация](README.md) › Пользователи и клиентские конфигурации

## Модель пользователей

Пользователи **глобальны**: одно имя и пароль работают на всех туннелях. Протокол — свойство туннеля, а не пользователя. Каждый пользователь может одновременно аутентифицироваться на всех туннелях.

> **Никогда не выдавайте `root` или любую учётную запись с командной оболочкой в качестве логина VPN.** Пользователи панели предназначены только для перенаправления: утечка такого логина лишает лишь доступа к туннелю, утечка `root` — всего сервера. Создайте отдельного пользователя панели для каждого, включая себя.

## Управление пользователями

```bash
sudo rovunet users add                              # one user
sudo rovunet users bulk_add --count=50 --prefix=user  # user001…user050, random passwords, up to 500
sudo rovunet users list                             # users and their configurations
sudo rovunet users remove                           # remove a user
```

Выдавайте каждому человеку собственного пользователя, чтобы при потере телефона отозвать только его доступ.

## Получение конфигураций

| Команда | Результат |
|---|---|
| `sudo rovunet users configs` | Все конфигурации всех пользователей на всех туннелях |
| `sudo rovunet tunnel share <tag>` | Конфигурация одного туннеля; спрашивает, чьи учётные данные вписать |
| `sudo rovunet tunnel share <tag> --user alice` | VLESS: ссылки `rovunet://` и `vless://` для alice |
| `sudo rovunet export-clients --user alice --format rovunet` | Список ссылок alice для скриптов; `--annotated` подписывает каждую туннелем |

Для туннелей DNSTT при выдаче спрашивается профиль **DNSTT** или **NoizDNS**. Оба используют один сервер; NoizDNS включает обход DPI на клиенте (труднее распознать, медленнее).

Конфигурация содержит учётные данные пользователя. Передавайте её по личному каналу, никогда в публичной группе.

## Форматы экспорта

| Формат | Схема | Где используется |
|---|---|---|
| Собственный | `rovunet://` | Приложение Rovunet. Несёт полный профиль, коллекцию (группу) пользователя и, начиная с v33, учётные данные без потерь, включая символы вроде `\|` |
| Стандартный VLESS | `vless://` | Любой клиент VLESS (v2rayNG, Hiddify, NekoBox…), печатается рядом с каждой конфигурацией VLESS |
| Ядро Xray | `rovunet://` (тип `xray`) или `vless://`, `hysteria2://`, файл `.conf` WireGuard | По одной на пользователя на каждом ядре; см. [Ядра Xray](xray-cores.md) |
| Устаревший | `slipnet://` | Старые версии приложения; по-прежнему принимается |

### Коллекции в приложении

Приложение группирует импортированные конфигурации по серверу и пользователю, так что все пути одного пользователя образуют одну коллекцию. Soar с бэкендом direct не требует входа, но печатается для каждого пользователя отдельно и попадает в его коллекцию. Профили ядер Xray печатаются для каждого пользователя в той же коллекции.

## Адрес сервера

Конфигурации SSH over TLS на собственном порту, SSH и SOCKS5 содержат IP сервера. На облачных серверах (Oracle, AWS, GCP, Azure) у сетевого интерфейса только частный IP, поэтому панель ищет публичный: собственный IP сервера, если он публичный, иначе IP записи `ns.<домен>` или домена NaïveProxy. Если ничего не найдено, панель один раз спрашивает и сохраняет ответ.

```bash
sudo rovunet config address 203.0.113.7   # an IP or hostname, without a port
sudo rovunet config address auto          # detect again
```

Конфигурации DNS-туннелей, Soar, NaïveProxy, VLESS и SSH over TLS через Naïve подключаются по домену и от него не зависят.

## Клиентские приложения

- **[Rovunet для Android](https://github.com/msVPNco/rovunet-android)** (рекомендуется): импортирует ссылки `rovunet://`, объединяет пути каждого пользователя в коллекцию, подключает выбранный путь без обязательного пинга и предлагает отдельные HTTPS-проверки через настоящий туннель.
- **Стандартные клиенты**, например v2rayNG, Hiddify или NekoBox: используйте ссылки `vless://` и файлы ядер Xray.

Далее: [Ядра Xray](xray-cores.md)
