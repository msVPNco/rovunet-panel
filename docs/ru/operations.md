## Обновление

```bash
sudo rovunet update
```

Обновление загружает последний выпуск, сверяет его с SHA256SUMS выпуска, атомарно заменяет бинарный файл (с откатом, если установка не удалась), обновляет транспортные бинарные файлы и пересоздаёт службы. Туннели, пользователи и ключи не затрагиваются, существующие клиентские ссылки продолжают работать.

### Переход с прежнего имени

Сервер, установленный под прежним именем панели (команда `slipgate`, `/etc/slipgate`), один раз обновляется старой командой и переносится автоматически:

```bash
sudo slipgate backup
sudo slipgate update
sudo rovunet tunnel status
```

Миграция останавливает старые службы, переносит `/etc/slipgate` в `/etc/rovunet`, переписывает сохранённые пути, не трогая паролей, переименовывает системных пользователей и группы с теми же UID и GID, пересоздаёт службы как `rovunet-*`, меняет конфигурацию sshd только после проверки `sshd -t`, делает `config.json` доступным только владельцу и устанавливает команду как `/usr/local/bin/rovunet`. Сервер с исходным SlipGate переходит так же:

```bash
curl -fsSL -o /tmp/rovunet https://github.com/msVPNco/rovunet-panel/releases/latest/download/rovunet-linux-amd64
sudo install -m 755 /tmp/rovunet /usr/local/bin/rovunet
sudo rovunet post-update
```

## Резервное копирование и восстановление

Резервная копия содержит всё, чтобы запустить ту же установку на другом сервере: конфигурацию, закрытые ключи и сертификаты всех туннелей, всех пользователей с паролями и ядра Xray. После восстановления на другом сервере те же туннели возвращаются с теми же ключами, и клиенты работают без новых ссылок.

```bash
sudo rovunet backup                      # asks: save to a file, or print text to copy
sudo rovunet backup /root/rovunet-backup.txt
sudo rovunet restore /root/rovunet-backup.txt
ssh root@old rovunet backup - | ssh root@new rovunet restore - --yes   # server to server
```

Резервная копия — один блок текста между `-----BEGIN ROVUNET BACKUP-----` и `-----END ROVUNET BACKUP-----`. В ней все закрытые ключи и пароли: храните её в тайне. Копии, сделанные под прежним именем, тоже восстанавливаются.

Восстановление на новом сервере:

1. Установите панель; когда мастер спросит о транспортах, нажмите Ctrl-C — восстановление настроит их само.
2. Выполните `sudo rovunet restore` и вставьте текст или укажите файл.
3. Направьте DNS-записи на новый IP; восстановление перечисляет записи, которые нужно изменить (`ns.<домен>` и домены NaïveProxy).

Восстановление устанавливает транспортные бинарные файлы, записывает ключи и конфигурацию, создаёт пользователей, открывает порты брандмауэра, заново настраивает WARP, если он был включён, запускает все службы и ядра Xray. Всё, что уже было на сервере, заменяется, предварительно сохранившись в `/root/rovunet-pre-restore-<дата>.txt`.

`rovunet config export` печатает только `config.json` без ключей: для переноса сервера используйте `backup`.

## Мониторинг

| Команда | Показывает |
|---|---|
| `sudo rovunet stats` | Панель в реальном времени: CPU, RAM, трафик, подключения по протоколам, состояние туннелей |
| `sudo rovunet tunnel status` | Все туннели и ядра Xray с состоянием служб |
| `sudo rovunet tunnel status <tag>` | Подробности туннеля: ключи, порт, MTU, имена, тип издателя и срок действия сертификата |
| `sudo rovunet diag` | Проверки: службы, порты, ключи, разрешение DNS, сохранение после перезагрузки |
| `sudo rovunet tunnel logs <tag>` | Журнал службы туннеля |

Сведения о сертификатах отмечают просроченные, истекающие (менее 14 дней) и нечитаемые сертификаты.

## Исходящий WARP (необязательно)

Cloudflare WARP может нести исходящий трафик сервера — когда нужные пользователям сайты отвергают IP сервера или как дополнительный узел. Включается в интерактивном меню. Добавляет задержку и зависимость от Cloudflare. Soar с бэкендом direct, VLESS и ядра Xray WARP не используют.

## Брандмауэр

Панель открывает порты туннелей и ядер через UFW, firewalld или iptables — что активно. С iptables она записывает открытые ею порты в `/etc/iptables/rovunet-ports` и при загрузке вставляет только их, не трогая правила других инструментов (Docker, fail2ban).

## Файлы и службы

| Путь | Содержимое |
|---|---|
| `/etc/rovunet/config.json` | Основная конфигурация: туннели, пользователи, маршрутизация (только владелец) |
| `/etc/rovunet/tunnels/<tag>/` | Ключи, сертификаты и конфигурация туннеля |
| `/etc/rovunet/vless.secret` | Общий секрет сервера, из которого выводятся UUID и пути VLESS |
| `/etc/rovunet/core/<имя>/` | Ядро Xray: `server.json`, `meta`, `clients/` устройств |
| `/usr/local/bin/rovunet` | Панель со встроенными серверами SOCKS5, Soar, SSH over TLS и VLESS |
| `/usr/local/bin/dnstt-server`, `slipstream-server`, `vaydns-server`, `caddy-naive` | Транспортные бинарные файлы |
| `/usr/local/bin/xray` | Закреплённое ядро Xray для `core-install` |
| `/etc/iptables/rovunet-ports` | Порты, открытые панелью в iptables |

| Юнит systemd | Назначение |
|---|---|
| `rovunet-dnsrouter` | DNS-маршрутизатор на порту 53 |
| `rovunet-socks5` | Встроенный SOCKS5-прокси |
| `rovunet-<tag>` | По одному на туннель |
| `rovunet-core-<имя>` | По одному на ядро Xray |
| `rovunet-iptables` | Восстанавливает порты брандмауэра панели при загрузке |

## Удаление

```bash
sudo rovunet uninstall
```

Удаляет все службы, конфигурации, бинарные файлы, системного пользователя и пользователей SSH-туннелей. DNS-записи остаются; при необходимости удалите их у DNS-провайдера.
