# Лимиты и ссылки подписки

[Документация](README.md) › Лимиты и ссылки подписки

## Безлимитные и ограниченные пользователи

При добавлении пользователя (`sudo rovunet users add`) панель спрашивает **безлимит или лимит**. По умолчанию — безлимит. Для ограниченного пользователя запрашиваются число **дней** и трафик в **ГБ**; оба значения по умолчанию безлимитны, так что можно ограничить только время, только трафик или оба. `users bulk_add` принимает те же лимиты для многих пользователей сразу.

```bash
sudo rovunet users list     # срок, квота и расход каждого пользователя, остановленные пользователи
sudo rovunet users renew    # вернуть остановленного: тот же логин, та же ссылка подписки, расход обнуляется
```

- 1 ГБ — это 1024³ байт; считаются и исходящий, и входящий трафик.
- Таймер systemd (`rovunet-user-expiry.timer`) проверяет каждые 5 минут. Пользователь с истёкшим сроком или исчерпанной квотой **останавливается**: доступ снимается, но логин и ссылка подписки сохраняются, чтобы `users renew` мог их вернуть.
- Смена пароля сохраняет лимиты пользователя и выдаёт новую ссылку подписки.

### Что считается

Лимит трафика возможен только для трафика, который панель умеет измерять. Поэтому ограниченный пользователь получает только такие конфигурации:

| Считается (выдаётся ограниченным) | Не считается (только безлимитным) |
|---|---|
| VLESS поверх WebSocket | SSH, SSH поверх TLS, NaïveProxy |
| VLESS + REALITY и VLESS + XHTTP, пока статистика этого ядра отвечает (проверяет `sudo rovunet diag`) | DNS-туннели, Soar, Hysteria 2, WireGuard |

Панель применяет это правило и на сервере, а не только в выдаваемых конфигурациях. У пользователя с лимитом **нет SSH-аккаунта** и нет входа в NaïveProxy, SOCKS5, Hysteria 2 и WireGuard, поэтому сохранённая ранее конфигурация (например, когда он был без лимита) перестаёт работать, в том числе после `users renew`. Его запись, лимит и ссылка подписки остаются. Если все пользователи ядра Hysteria 2 или WireGuard ограничены, ядро остановлено, пока не появится пользователь без лимита.

Некоторый доступ нельзя привязать к одному пользователю, и на него квоты не действуют: Soar без входа, DNS-туннели без SSH-аккаунта за ними и ядра, созданные устаревшим параметром `--devices`.

## Ссылки подписки

У каждого пользователя, ограниченного или нет, есть **одна ссылка** со всеми его конфигурациями:

```
https://your-domain/sub/<token>.json
```

Вставьте её в меню **Subscriptions** приложения. Это статический JSON-список, который отдаёт сайт NaïveProxy на порту 443, поэтому нужен лишь туннель NaïveProxy. Ссылка печатается после создания пользователя и командой `sudo rovunet users configs`.

- Ссылка обновляется сама: после любого изменения пользователей или туннелей, после обновления и каждые 5 минут для ограниченных пользователей.
- Токен случайный, ссылку нельзя угадать. Храните её в тайне, как и сами конфигурации.
- Пока ограниченный пользователь остановлен, ссылка не выдаёт новых конфигураций; после `users renew` та же ссылка снова работает.

## Файл состояния аккаунта

Рядом с каждой подпиской есть файл состояния: та же ссылка, где `.json` заменено на `.status.json`.

```
https://your-domain/sub/<token>.status.json
```

Он сообщает приложению, что ещё доступно аккаунту, чтобы показать оставшийся трафик и дни и объяснить, почему конфигурации перестали работать. Он ничего не даёт: ограничения сервер применяет сам, а в файле нет ни паролей, ни конфигураций. Сам файл подписки не изменился.

```json
{
  "version": 1,
  "server_id": "<32 hex>",
  "account_id": "<32 hex>",
  "period_id": "<32 hex>",
  "account_status": "active",
  "expires_at": "2026-12-01T00:00:00Z",
  "limit_bytes": 10737418240,
  "used_bytes": 1234567,
  "metering_status": "complete",
  "sampled_at": "2026-11-08T10:00:00Z",
  "generated_at": "2026-11-08T10:00:03Z",
  "revision": 7
}
```

| Ключ | Значение |
|---|---|
| `server_id` | Эта панель. Случайный, создаётся один раз, не зависит от IP или имени сервера. |
| `account_id` | Этот аккаунт. Сохраняется при `users renew` и `users passwd`; удалённый и снова добавленный пользователь получает новый. |
| `period_id` | Текущий период. `users renew` начинает новый, чтобы приложение не складывало два периода. |
| `account_status` | `active`, `expired` или `limit_reached`. |
| `expires_at` | Время окончания (UTC) или `null`, если его нет. |
| `limit_bytes` / `used_bytes` | Лимит и израсходованный в этом периоде трафик, в обе стороны, 1 ГБ = 1024³ байт. Оба `null` у пользователя без лимита трафика (его трафик считается не на всех протоколах). |
| `metering_status` | `complete`, `partial` (одно ядро не ответило при последнем чтении или файл счётчика не прочитался, число может быть занижено), `unavailable` (ни разу не читалось) или `not_metered` (без лимита трафика). |
| `sampled_at` | Последнее чтение счётчиков Xray, при котором ответили все ядра. Неудачное чтение его не сдвигает, поэтому старое число не выглядит свежим. `null` без лимита трафика или до первого полного чтения. Счётчик VLESS отстаёт от `generated_at` не более чем на 15 секунд. |
| `generated_at` | Когда записан файл. Сравнивайте с HTTP-заголовком `Date`, чтобы неверные часы телефона не мешали. |
| `revision` | Растёт на единицу, когда меняется что-либо, кроме времени. Относится к этому URL: после `users passwd` у ссылки новый токен, и новый файл снова начинается с 1 (с теми же `account_id` и `period_id`), поэтому приложение, перешедшее на новую ссылку, сравнивает заново. |

- Файл перезаписывается при каждом изменении пользователей и при каждой проверке лимитов (каждые 5 минут, пока у кого-то есть лимит). Он отдаётся с `Cache-Control: no-store`.
- После обновления или на новом сервере `metering_status` равен `unavailable` до первой проверки лимитов, примерно через 5 минут (таймер добавляет случайную задержку до 20 секунд).
- У остановленного пользователя файл состояния остаётся (с `expired` или `limit_reached`), а файл подписки удаляется. У удалённого совсем нет ни того, ни другого. **404 не означает «истёк»**: так же отвечает и старая панель, и удалённый аккаунт, поэтому приложению следует показать «сведения об аккаунте недоступны».
- Как и ссылка подписки, ссылка состояния содержит токен: кто её знает, видит расход аккаунта.

## Несколько адресов одного сервера

Если один IP сервера заблокирован, другие IP того же сервера могут работать. Добавьте их списком через запятую; первый — основной адрес (`auto` определяет его сам):

```bash
sudo rovunet config address auto,198.51.100.9
```

Тогда ссылки подписки несут каждую конфигурацию, привязанную к адресу, по одному разу на каждый дополнительный адрес, и приложение может перейти на другой адрес. Каждый дополнительный адрес должен действительно вести на этот сервер (IP на сетевом интерфейсе или имя хоста, указывающее на него), с теми же открытыми портами. Это добавляет адреса, а не локации. `sudo rovunet config address auto` убирает дополнительные адреса.
