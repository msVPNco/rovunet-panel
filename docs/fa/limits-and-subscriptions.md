# سهمیه و لینک اشتراک

[مستندات](README.md) › سهمیه و لینک اشتراک

## کاربر آزاد یا سهمیه‌ای

هنگام افزودن کاربر (`sudo rovunet users add`) پنل می‌پرسد **آزاد یا سهمیه‌ای**؛ پیش‌فرض «آزاد» است. برای کاربر سهمیه‌ای تعداد **روز** و حجم **گیگابایت** را می‌پرسد و هر دو به‌طور پیش‌فرض آزادند؛ پس می‌توانید فقط زمان، فقط حجم یا هر دو را محدود کنید. `users bulk_add` هم همین محدودیت‌ها را برای چند کاربر یک‌جا می‌پذیرد.

```bash
sudo rovunet users list     # انقضا، سهمیه و مصرف هر کاربر و کاربران متوقف‌شده
sudo rovunet users renew    # برگرداندن کاربر متوقف‌شده: همان لاگین، همان لینک اشتراک، مصرف از صفر
```

- هر ۱ گیگابایت برابر ۱۰۲۴³ بایت است و آپلود و دانلود هر دو شمرده می‌شوند.
- یک تایمر systemd (‏`rovunet-user-expiry.timer`) هر ۵ دقیقه بررسی می‌کند. کاربری که منقضی شده یا کل سهمیه را مصرف کرده **متوقف** می‌شود: دسترسی‌اش برداشته می‌شود ولی لاگین و لینک اشتراکش نگه داشته می‌شود تا `users renew` بتواند برش گرداند.
- عوض کردن رمز کاربر محدودیت‌هایش را حفظ می‌کند و لینک اشتراک جدید می‌دهد.

### چه چیزی شمرده می‌شود

محدودیت حجم فقط روی ترافیکی ممکن است که پنل بتواند اندازه بگیرد. بنابراین کاربر سهمیه‌ای فقط این کانفیگ‌ها را می‌گیرد:

| شمرده می‌شود (به کاربر سهمیه‌ای داده می‌شود) | شمرده نمی‌شود (فقط به کاربر آزاد داده می‌شود) |
|---|---|
| VLESS روی WebSocket | SSH، SSH روی TLS، NaïveProxy |
| VLESS + REALITY و VLESS + XHTTP، تا وقتی آمار آن هسته جواب می‌دهد (‏`sudo rovunet diag` بررسی می‌کند) | تونل‌های DNS، Soar، Hysteria 2، WireGuard |

پنل این قاعده را روی سرور هم اجرا می‌کند، نه فقط در کانفیگ‌هایی که چاپ می‌کند. کاربر حجمی **حساب SSH ندارد** و در NaïveProxy، SOCKS5، Hysteria 2 و WireGuard هم ورود ندارد؛ پس کانفیگی که قبلاً گرفته (مثلاً وقتی نامحدود بود) از کار می‌افتد، حتی بعد از `users renew`. رکورد، محدودیت و لینک اشتراکش می‌ماند. اگر همهٔ کاربران یک هستهٔ Hysteria 2 یا WireGuard حجمی باشند، آن هسته تا آمدن یک کاربر نامحدود متوقف می‌ماند.

بعضی دسترسی‌ها را نمی‌شود به یک کاربر وصل کرد و خارج از هر سهمیه‌اند: Soar بدون ورود، تونل‌های DNS که حساب SSH پشتشان نیست، و هسته‌های ساخته‌شده با گزینهٔ قدیمی `--devices`.

## لینک اشتراک

هر کاربر، سهمیه‌ای یا آزاد، **یک لینک** دارد که همهٔ کانفیگ‌هایش را حمل می‌کند:

```
https://your-domain/sub/<token>.json
```

آن را در منوی **Subscriptions** اپ بچسبانید. فایل یک فهرست JSON ثابت است که سایت NaïveProxy روی پورت ۴۴۳ سرو می‌کند؛ پس فقط به یک تونل NaïveProxy نیاز دارد. لینک بعد از ساخت کاربر و با `sudo rovunet users configs` چاپ می‌شود.

- لینک خودکار به‌روز می‌ماند: بعد از هر تغییر کاربر یا تونل، بعد از به‌روزرسانی، و برای کاربران سهمیه‌ای هر ۵ دقیقه.
- توکن تصادفی است و لینک قابل حدس نیست؛ مثل خود کانفیگ‌ها محرمانه نگهش دارید.
- وقتی کاربر سهمیه‌ای متوقف شود لینک کانفیگ جدید نمی‌دهد؛ بعد از `users renew` همان لینک دوباره کار می‌کند.

## فایل وضعیت حساب

کنار هر اشتراک یک فایل وضعیت هست: همان لینک، با `.status.json` به جای `.json`.

```
https://your-domain/sub/<token>.status.json
```

این فایل به اپ می‌گوید حساب هنوز چه چیزی دارد، تا اپ حجم و روز باقی‌مانده را نشان دهد و بگوید چرا کانفیگ‌ها از کار افتاده‌اند. هیچ دسترسی‌ای نمی‌دهد: سرور خودش محدودیت‌ها را اعمال می‌کند و در فایل رمز یا کانفیگی نیست. خود فایل اشتراک تغییری نکرده است.

```json
{
  "version": 1,
  "server_id": "<32 hex>",
  "account_id": "<32 hex>",
  "period_id": "<32 hex>",
  "account_status": "active",
  "expires_at": "2026-12-01T00:00:00Z",
  "limit_bytes": 10737418240,
  "used_bytes": 1234567,
  "metering_status": "complete",
  "sampled_at": "2026-11-08T10:00:00Z",
  "generated_at": "2026-11-08T10:00:03Z",
  "revision": 7
}
```

| کلید | معنی |
|---|---|
| `server_id` | همین پنل. تصادفی، یک بار ساخته می‌شود و به آی‌پی یا نام سرور وابسته نیست. |
| `account_id` | همین حساب. با `users renew` و `users passwd` می‌ماند؛ کاربری که حذف و دوباره اضافه شود شناسهٔ تازه می‌گیرد. |
| `period_id` | دورهٔ فعلی. ‏`users renew` دورهٔ تازه شروع می‌کند تا اپ هیچ‌وقت دو دوره را با هم جمع نزند. |
| `account_status` | ‏`active`، `expired` یا `limit_reached`. |
| `expires_at` | زمان انقضا (UTC)، یا `null` یعنی بدون انقضا. |
| `limit_bytes` / `used_bytes` | سقف حجم و مصرف همین دوره، هر دو جهت، ۱ گیگ = ۱۰۲۴³ بایت. برای کاربر بدون سقف حجم هر دو `null` است (ترافیکش در همهٔ پروتکل‌ها شمرده نمی‌شود). |
| `metering_status` | ‏`complete`، `partial` (یک هسته در آخرین خواندن جواب نداد یا یک فایل شمارنده خوانده نشد، و عدد شاید کم باشد)، `unavailable` (هرگز خوانده نشده) یا `not_metered` (بدون سقف حجم). |
| `sampled_at` | آخرین خواندن شمارنده‌های Xray که همهٔ هسته‌ها در آن جواب دادند. خواندن ناموفق آن را جلو نمی‌برد، تا عدد قدیمی تازه به نظر نرسد. بدون سقف حجم یا پیش از اولین خواندن کامل `null` است. شمارندهٔ VLESS حداکثر ۱۵ ثانیه از `generated_at` عقب است. |
| `generated_at` | زمان نوشتن فایل. با هدر `Date` در پاسخ HTTP مقایسه کنید تا ساعت غلط گوشی خطا نسازد. |
| `revision` | هر بار که چیزی جز زمان‌ها عوض شود یکی بالا می‌رود. مخصوص همین URL است: بعد از `users passwd` لینک توکن تازه دارد و فایل تازه دوباره از ۱ شروع می‌کند (با همان `account_id` و `period_id`)، پس اپی که لینک تازه را دنبال می‌کند مقایسه را از نو شروع کند. |

- فایل بعد از هر تغییر کاربر و در هر بررسی محدودیت‌ها (هر ۵ دقیقه، تا وقتی کاربری محدودیت دارد) بازنویسی می‌شود و با `Cache-Control: no-store` سرو می‌شود.
- کاربر متوقف‌شده فایل وضعیت را نگه می‌دارد (با `expired` یا `limit_reached`) ولی فایل اشتراکش حذف می‌شود. کاربری که کاملاً حذف شود هیچ‌کدام را ندارد. **۴۰۴ به معنی منقضی‌شدن نیست**: پنل قدیمی‌تر یا حساب حذف‌شده هم همین را برمی‌گرداند، پس اپ باید «اطلاعات حساب در دسترس نیست» نشان دهد.
- لینک وضعیت هم مثل لینک اشتراک توکن را دارد: هر کس آن را داشته باشد مصرف حساب را می‌بیند.

## چند آدرس برای یک سرور

اگر یک آی‌پی سرور مسدود شد، آی‌پی‌های دیگر همان سرور شاید کار کنند. آن‌ها را با فهرست جداشده با ویرگول اضافه کنید؛ اولی آدرس اصلی است (‏`auto` یعنی تشخیص خودکار):

```bash
sudo rovunet config address auto,198.51.100.9
```

لینک‌های اشتراک آن‌وقت هر کانفیگ وابسته به آدرس را به ازای هر آدرس اضافه یک بار می‌آورند تا اپ بتواند به آدرس دیگر برود. هر آدرس اضافه باید واقعاً به همین سرور برسد (آی‌پی روی کارت شبکه یا نام میزبانی که به آن اشاره می‌کند) و پورت‌ها باز باشند. این آدرس اضافه می‌کند، نه لوکیشن. ‏`sudo rovunet config address auto` آدرس‌های اضافه را پاک می‌کند.
