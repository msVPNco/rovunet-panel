# هسته‌های Xray

[مستندات](README.md) › هسته‌های Xray

هستهٔ Xray یک سرور Xray جداست که پنل کنار تونل‌ها نصب و مدیریت می‌کند و چهار پروتکلی را می‌دهد که سرورهای داخلی پنل ندارند. هر کاربر پنل روی هر هسته یک کانفیگ دارد؛ ⁦`users configs`⁩ آن را کنار تونل‌های همان کاربر چاپ می‌کند و در اپ Rovunet هم در گروه همان کاربر قرار می‌گیرد.

| پروتکل | انتقال | گواهی | مناسب برای |
|---|---|---|---|
| **VLESS + REALITY** (XTLS Vision) | TCP | لازم نیست: دست‌دهی شبیه یک سایت واقعی است (⁦`--target`⁩) | شبکه‌هایی که TLS به سایت‌های شناخته‌شده از آن‌ها رد می‌شود |
| **VLESS + XHTTP** | TCP، درخواست‌های HTTP روی TLS | لازم، معتبر برای ⁦`--sni`⁩ | پشت CDN، یا جایی که WebSocket بسته است |
| **Hysteria 2** | UDP (QUIC) | لازم، معتبر برای ⁦`--sni`⁩ | شبکه‌های پرنوسان یا ناپایدار که UDP از آن‌ها رد می‌شود |
| **WireGuard** | UDP | لازم نیست | شبکه‌هایی که WireGuard را مسدود نمی‌کنند |

## انتخاب پروتکل

اینکه کدام پروتکل رد شود به شبکه بستگی دارد. روی یک شبکهٔ موبایل فیلترشده اندازه گرفتیم: VLESS روی WebSocket، **XHTTP** و **REALITY** سریع‌تر از همه وصل شدند، بعد NaïveProxy، SSH over TLS و SSH آمدند، و **WireGuard، Hysteria 2 و SOCKS5 اصلاً وصل نشدند** (UDP و ترافیک رمزنگاری‌نشده قطع می‌شد). این فقط یک شبکه است، نه قاعده: روی شبکهٔ خودتان هر کدام را آزمایش کنید. به همین دلیل نصب‌کننده REALITY و XHTTP را پیشنهاد می‌کند و خروجی کانفیگ‌ها را از سریع‌ترین به کندترین فهرست می‌کند ([کاربران و کانفیگ‌ها](users-and-configs.md#order) را ببینید).

## نصب یک هسته

نصب‌کننده (⁦`sudo rovunet install`⁩) گزینه‌های **VLESS + REALITY**، **VLESS + XHTTP**، **Hysteria 2** و **WireGuard** را کنار بقیهٔ پروتکل‌ها نشان می‌دهد و آن‌ها را بعد از ساخت اولین کاربر، روی اولین پورت آزاد پیش‌فرض راه می‌اندازد (REALITY: ⁦9443⁩، ⁦2096⁩ یا ⁦8880/tcp⁩؛ XHTTP: ⁦2096⁩، ⁦2087⁩ یا ⁦8880/tcp⁩؛ Hysteria 2: ⁦8443⁩، ⁦4443⁩ یا ⁦2096/udp⁩؛ WireGuard: ⁦51820–51822/udp⁩). XHTTP و Hysteria 2 از گواهی TLS ای استفاده می‌کنند که Caddy برای دامنهٔ NaïveProxy گرفته است، پس NaïveProxy هم باید انتخاب شود؛ اگر گواهی تا ۹۰ ثانیه آماده نشود، با یک پیام رد می‌شوند و بعداً هم می‌توان آن‌ها را اضافه کرد. هر هسته را بعداً هم می‌توان اضافه کرد:

**دو هستهٔ REALITY.** وقتی نصب‌کننده REALITY را روی یک سرور تازه راه می‌اندازد، هستهٔ دوم REALITY به نام ⁦`reality2`⁩ را هم کنار اولی می‌سازد: روی ⁦2087⁩، ⁦2053⁩ یا ⁦8443/tcp⁩ (اولین پورت آزاد) و با ظاهر یک سایت دیگر. این دو سایت هیچ‌وقت از یک شرکت نیستند (مثلاً دو سایت مایکروسافت با هم مسدود می‌شوند). هر کاربر روی هر دو هسته پیکربندی دارد، با همان شمارش و همان محدودیت‌ها؛ پس اگر شبکهٔ کاربر یک سایت یا یک پورت را ببندد، راه دیگری دارد. این کار فقط در نصب تازه انجام می‌شود: سروری که از قبل هستهٔ REALITY دارد دست‌نخورده می‌ماند، و هستهٔ دوم را هر زمان می‌توان دستی اضافه کرد، مثلاً:

```bash
sudo rovunet core-install --name reality2 --protocol reality --host SERVER_IP --port 2087 \
  --target www.apple.com:443 --sni www.apple.com
```

بعد از افزودن دستی هسته، یک بار ⁦`sudo rovunet expire-users`⁩ را بزنید یا تا ۵ دقیقه صبر کنید تا لینک‌های اشتراک آن را هم داشته باشند. لینک‌های هستهٔ دوم ⁦`Rovunet-reality2-<user>`⁩ نام دارند.

</div>

```bash
# VLESS + REALITY
sudo rovunet core-install --name r1 --protocol reality --host SERVER_IP \
  --target www.microsoft.com:443 --sni www.microsoft.com --port 9443

# VLESS + XHTTP
sudo rovunet core-install --name x1 --protocol xhttp --host vpn.example.com --sni vpn.example.com \
  --cert /path/fullchain.pem --key /path/privkey.pem --port 2096

# Hysteria 2
sudo rovunet core-install --name h1 --protocol hysteria2 --host vpn.example.com --sni vpn.example.com \
  --cert /path/fullchain.pem --key /path/privkey.pem --port 8443

# WireGuard
sudo rovunet core-install --name w1 --protocol wireguard --host SERVER_IP --port 51820
```

<div dir="rtl">

| گزینه | معنا |
|---|---|
| ⁦`--name`⁩ | نام هسته: ۱ تا ۳۱ نویسه از ⁦`a-z`⁩، ⁦`0-9`⁩ و ⁦`-`⁩ |
| ⁦`--protocol`⁩ | ⁦`reality`⁩، ⁦`xhttp`⁩، ⁦`hysteria2`⁩ یا ⁦`wireguard`⁩ |
| ⁦`--host`⁩ | نام یا IP عمومی که کلاینت به آن وصل می‌شود |
| ⁦`--sni`⁩ | نام گواهی، یا نام سروری که REALITY نشان می‌دهد (پیش‌فرض: ⁦`--host`⁩) |
| ⁦`--target`⁩ | فقط REALITY: سایت TLS واقعی که تقلید می‌شود، به شکل ⁦`host:port`⁩ |
| ⁦`--port`⁩ | پورت شنود (پیش‌فرض 8443)؛ باید آزاد باشد |
| ⁦`--devices`⁩ | حالت «هر دستگاه» به‌جای «هر کاربر»: این تعداد اطلاعات ورود مستقل (۱ تا ۱۰۰۰)، فقط به‌صورت فایل |
| ⁦`--cert`⁩، ⁦`--key`⁩ | XHTTP و Hysteria 2: مسیر گواهی و کلید خصوصی |

## نصب چه می‌کند

۱. آزاد بودن پورت را روی پروتکل درست بررسی می‌کند (TCP برای REALITY و XHTTP، UDP برای Hysteria 2 و WireGuard).  
۲. نسخهٔ پین‌شدهٔ Xray را که همراه همین release منتشر شده نصب می‌کند و با SHA256SUMS همان release تأییدش می‌کند. اگر ⁦`/usr/local/bin/xray`⁩ از قبل باشد، دست نمی‌خورد.  
۳. کانفیگ سرور را می‌نویسد و پیش از فعال شدن، Xray خودش آن را آزمایش می‌کند (⁦`xray run -test`⁩).  
۴. سرویس ⁦`rovunet-core-<name>`⁩ را می‌سازد و اجرا می‌کند و پورت را در فایروال باز می‌کند.  
۵. برای هر کاربر یک فایل کلاینت در ⁦`/etc/rovunet/core/<name>/clients/`⁩ می‌نویسد.

اگر هر مرحله‌ای شکست بخورد، هرچه ساخته شده بود پاک می‌شود.

## کاربران و کانفیگ‌ها

اطلاعات ورود هر کاربر از کلید مخفی خود هسته، نام کاربری و رمز ساخته می‌شود:

- ⁦`users add`⁩ به کاربر جدید روی همهٔ هسته‌ها کانفیگ می‌دهد؛ کانفیگ کاربران فعلی عوض نمی‌شود.
- ⁦`users remove`⁩ و ⁦`passwd`⁩ کانفیگ قبلی را ظرف چند ثانیه باطل می‌کنند. Xray هر تغییر را اول آزمایش می‌کند؛ اگر ردش کند، کانفیگ قبلی سر جایش می‌ماند.
- ⁦`users configs`⁩ و ⁦`export-clients --format rovunet`⁩ کانفیگ‌های هسته‌ای هر کاربر را به‌صورت پروفایل بومی ⁦`rovunet://`⁩ در گروه همان کاربر چاپ می‌کنند. ⁦`export-clients --format standard`⁩ لینک‌های سادهٔ ⁦`vless://`⁩ و ⁦`hysteria2://`⁩ را برای کلاینت‌های دیگر چاپ می‌کند. ⁦`users configs`⁩ زیر هر پروفایل هسته، لینک ساده یا فایل وایرگارد (با نام ⁦`rovunet.conf`⁩ ذخیره کنید) را هم چاپ می‌کند تا در هر اپ دیگری، مثل اپ رسمی WireGuard، وارد شود.
- کانفیگ سادهٔ هر کاربر در ⁦`/etc/rovunet/core/<name>/clients/<user>.txt`⁩ هم هست (برای WireGuard پسوند ⁦`.conf`⁩). یک کانفیگ WireGuard را هرگز هم‌زمان روی دو دستگاه استفاده نکنید.

## بکاپ

هسته‌ها در ⁦`rovunet backup`⁩ ذخیره و با ⁦`restore`⁩ دوباره راه‌اندازی می‌شوند. گواهی‌هایی که با ⁦`--cert`⁩/⁦`--key`⁩ داده‌اید بیرون از پنل‌اند و باید روی سرور جدید در همان مسیر باشند، وگرنه پنل گزارش می‌دهد آن هسته اجرا نشد.

## محدودیت‌ها

- XHTTP و Hysteria 2 گواهی را هنگام اجرا می‌خوانند. یک تایمر (⁦`rovunet-core-certs.timer`⁩، دو بار در روز) دستور ⁦`rovunet core-certs`⁩ را اجرا می‌کند که هستهٔ دارای گواهی تغییرکرده را دوباره راه‌اندازی می‌کند، پس گواهی تمدیدشده بدون هیچ کاری استفاده می‌شود. برای انجام فوری: ⁦`sudo rovunet core-certs`⁩.
- هسته‌هایی که پیش از v1.9.0 (به‌صورت «هر دستگاه») نصب شده‌اند همان‌طور کار می‌کنند؛ برای وصل شدن به کاربران پنل، دوباره نصبشان کنید.
