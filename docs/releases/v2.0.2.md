# Rovunet Panel v2.0.2

This patch restores automatic public-certificate retrieval for Slipstream on
the existing subscription origin. The panel already generated the shared trust
file, but the legacy Caddy allowlist did not route `.trust.json`. Normal panel
Update now regenerates that configuration using the corrected route.

Use the existing saved source after updating the server. Both Slipstream SOCKS
and SSH keep their profile IDs, domain/certificate bindings and public DER hashes.
The shared suffix is `.trust.json`, including for a `.windows.json` source;
`.windows.trust.json` is not an endpoint. v2 is not automatically enabled and
certificate identity changes still require the client's reviewed recovery policy.

Fresh installation prepares protocol engines before the first-account prompt.
An occupied Linux username prompts for a different name without resetting that
account. Leftover engines use the authenticated update transaction, and an orphan
bootstrap receipt with no executable is archived privately before fresh setup.
Invalid or still-active bootstrap state remains a recovery condition.
An interrupted runtime update also recovers a missing authenticated AWG
provenance manifest before recording the runtime family or restarting cores.

Uninstall covers owned services, timers, SSH settings, accounting data and new
engine artifacts. It retains a root-only recovery archive before deleting active
data. Shared-bin files are removed only when an exact ownership receipt and digest
match; unknown, changed or still-used files are preserved and reported. Custom SSH
blocks fail closed for explicit review. Administrator accounts are not adopted.
The exact generated resolved stub override is removed after a private backup;
custom resolver overrides are preserved for review. Shared firewall rules,
package dependencies and administrator resolver files are retained.

Profile counts remain 30 unrestricted / 29 time-only / 6 traffic-limited on both
feed aliases. Recorded consumption, uncertainty, connection credentials, saved
URLs and account/period/profile identities must be preserved on upgrade.

The signed manifest and exact public source identify all release bytes. The
existing production signing root is retained. Automated release assembly reuses
authenticated unchanged assets and accepts regenerated panel/source bytes only
if they exactly match the locally signed manifest; CI has no private signing key.

Acceptance receipts and exact hashes accompany the owner's final report. Real
app/ISP reachability, physical ARM64, off-site signer custody and complete
fresh-target provider/runtime recovery are separate qualifications. No managed
Slipstream session API, silent pin rotation or exact simultaneous-device cap is
introduced by this patch.
