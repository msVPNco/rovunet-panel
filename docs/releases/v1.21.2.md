# v1.21.2 — functional update and stable subscription migration

The owner authorized publication on 2026-11-13 after the scoped private review. This release delivers the tested functional changes. The four broader security/operational qualification gates in release-gates.json remain open; they are not relabeled verified. Candidate runtime binaries are not promoted, and restricted account eligibility is unchanged.

## Install, update and app refresh

Normal installation and update complete the missing managed cores. Fully eligible unlimited accounts receive 24 subscription profiles in both Android and Windows feeds. Existing .json and .windows.json addresses, tokens, account IDs and item IDs remain. Current Windows 0.1.2-preview.5 supports the full feed; the public 0.1.1 Beta reader keeps 23 supported entries; 0.1.0 Beta keeps 22. The two added Windows items use standard AWG/SS encodings so older readers skip unsupported entries without rejecting the saved feed. Previously published native items retain their envelope and identity. Upgrade that older app to use AWG. Timed accounts intentionally exclude shared-key Soar Direct; quota accounts retain their enforceable subset.

Old account-managed Hy2 cores are migrated once to Salamander using the existing state seed, endpoint and per-user auth. New Hy2 defaults to Salamander. After the server update, press Update on the existing subscription in the app; do not delete it or resend the link. An explicit core-hy2-obfs NAME off is stored and survives future updates. Only the selected Hy2 core needs a migration restart; disabled/inactive cores stay stopped. A failed validation/startup retains/restores private recovery state. The mode change intentionally updates the one Hy2 profile; cached plain profiles need the app refresh. WG remains a separate ordinary WireGuard profile, with AWG as its existing independent alternative; no silent profile substitution.

Running update when already at this release rechecks missing setup and pending Hy2 migration without repeating general transport/service replacement. Repeated completion does not recreate accounts, keys or cores. Missing DNS/cert/TUN/port prerequisites are reported honestly.

## Transition from the old private preview

The already-installed 1.20.1-managed-preview.3 binary rejects its own public Update before making any request. A new GitHub release cannot alter that old compiled guard. Use the signed release's reviewed preview-to-v1.21.2 package once, then run rovunet update to reconcile setup/Hy2 and use normal updates afterward. The promotion itself preserves existing core/service files and permits only the two approved added Windows items; existing profiles remain unchanged except approved display names.

## Publishing and trust

GitHub Actions builds/tests an unsigned draft and a downloadable artifact. The private signing key remains in the owner's existing Windows DPAPI vault; it is not exported into GitHub secrets. Locally verified final bytes, source commit and acceptance record are signed; only the authenticated complete draft is made Latest. Existing published tags/assets are preserved.

The ordinary runtime pins and traffic restrictions remain unchanged. Dependency/source/runtime/ABI inventory and observed UDP filtering, cold-start AWG, retained established Xray streams, provider/full-restore gaps and physical-device/off-site-custody limits remain documented in the engineering ledger. This is not a claim that every protocol works on every operator network or that all full acceptance work is finished.
